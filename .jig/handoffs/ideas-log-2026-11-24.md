## Built
The whole of ideas-log: Parts A, B and C, the bug role's spec bug-merge-log-one-write (Bug-for: ideas-log), and the syncs with phase-types, bug-deferred-scope and roadmap-labels.
- **A, the ideas log.** `jig init` writes `.jig/ideas.md`, and the log's seed has no `## Open`. Ideas are in the decision entry's form, with ids from the log's counter, and `jig merge` numbers them. The hook checks them under M2: status, decided, an id in both files, sections, Touches, `D-?` on trunk. R3 and append files take them. Every reader by id reads both files through one join, `with_ideas`: `jig decision`, `reading-list` (per page, and `--claims`), peers, the gate's Proposed warning, holds and chains, removed-entry history, the Touches backfill.
- **B, the fold and its writers.** `jig update --apply` folds an old log's `## Open` into the ideas file byte for byte; in a metarepo, `--fold-ideas` does it in a job. The hook then refuses an added `## Open` heading or an Open/Proposed entry. Staging, `--merge-log`, survey/sweep and the kickoff write ideas to the ideas file. In a metarepo the ideas file is an entry file, recorded by itself. Citations, pin bumps, the sync report (`(accepted)`) and move-line targets read either file. RULES.md and the stage, update, redocument and retro skills name the ideas file. STAMP is 12.
- **The bug spec.** `--merge-log` builds one plan of every file's final text and every removal, and writes each path once. Nothing in it reads a file the plan holds, and a path both written and removed is refused.
- **C, labels and the list.** An idea's `(labels …)` line is read by roadmap-labels' `split_labels` and checked by `label_problems`, against the glossary a scope uses. Own glossary: every line, so dropping a named term is refused. The metarepo's: only lines a commit adds or changes. Unreachable: passes with a warning. An unfolded log's `## Open` labels are judged the same way. `jig ideas [--label]` lists ideas (an unfolded log's open entries included), with each pararepo's in a metarepo. `family_report` reads the metarepo's ideas. Docs: records, glossary, commands, metarepos.
