## Built
Parts A and B of ideas-log (Part C waits for roadmap-labels' Part A on trunk), and the bug role's spec bug-merge-log-one-write (Bug-for: ideas-log).
- **A, the ideas log:** `.jig/ideas.md`, written by `jig init` (the log's seed loses `## Open`). Ideas are entries in the decision entry's form with ids from the log's counter. `jig merge` numbers them, ideas first. The hook checks them (M2: status, decided, an id in both files, sections, Touches, `D-?` on trunk). R3 and append files take them. Every reader by id reads both files through one join (`with_ideas`): `jig decision`, `reading-list` (per page, and `--claims`), peers, the gate's Proposed warning, holds/chains, removed-entry history.
- **B, the fold and its writers:** `jig update --apply` folds an old log's `## Open` into `.jig/ideas.md` byte for byte, and in a metarepo `jig update --apply --fold-ideas` does it in a job. The hook then refuses an added `## Open` heading or Open/Proposed entry in the log. Staging, `--merge-log`, survey/sweep and the kickoff write ideas to the ideas file. In a metarepo the ideas file is an entry file recorded by itself (no M3 line, M4 by merge). Citations, pin bumps, the sync report (`(accepted)`) and move-line targets read either file. RULES.md and the stage, update, redocument and retro skills name the ideas file.
- **Bug spec:** `--merge-log` builds one plan of every file's final text and removal, and writes each path once. A path both written and removed is refused. STAMP is 12.
